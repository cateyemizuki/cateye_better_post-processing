## 2. 现状摘要（调研结论）

### 2.1 cateye_mai_cross-chat_recall（v0.2.1）

- 单包结构：`plugin.py`(830 行，配置模型 + 插件主体) + `scanner.py`（扫描/总结调度）+ `summarizer.py`（LLM 总结）+ `store.py`（SQLite 总结库）+ `injector.py`（注入块构造/插入）+ `helpers.py`（消息解析工具）+ `logging_setup.py`（插件目录文件日志，README 已注明"不符合规范、临时保留"）。
- 三个 Hook：`maisaka.planner.before_request`（注入+触发扫描，BLOCKING/NORMAL）、`maisaka.replyer.before_model_request`（注入，BLOCKING/NORMAL）、`chat.receive.after_process`（push 计数，OBSERVE）。
- 两个命令：`/ccr debug test`（强制注入标记，TTL 600s）、`/ccr clean`（清库），均 operator。
- **当前没有任何 @Tool 组件**——新增工具是全新能力。
- 总结库：`data/plugins/<plugin_id>/cross_chat_recall.db`，表 `private_summaries`，列含 `user_id(PK)/platform/private_stream_id/user_nickname/summary/start_ts/end_ts/user_msg_count/pending_resummarize/updated_at`；`SummaryStore` 提供 `get/get_many/upsert/set_pending/cleanup/clear/dump`。
- 昵称来源：消息 `message_info.user_info.user_nickname`（群名片 `user_cardname`）——`helpers.extract_message_fields` 的 `nickname` 字段已做兼容；聊天流字段 `user_nickname/user_cardname` 亦可取。
- 配置：`plugin/scan/summarize/inject/store/scope` 六节，`SUPPORTED_CONFIG_VERSION="0.2.1"`。README 与代码经通读核对一致（无虚报功能）。

### 2.2 cateye_duplicate_reply_guard（v1.1.3）

- 单文件插件：`plugin.py`(1192 行) + `intercept_log.py`(JSON Lines 轮转日志类 `InterceptLogger`)。**无 Command 组件**，纯 Hook 型。
- 5 个 Hook（全部 ErrorPolicy.SKIP + 函数体 try/except fail-open）：

| Hook | handler(name) | mode/order | 职责 |
|---|---|---|---|
| `maisaka.planner.before_request` | `self_message_id_scanner` | BLOCKING/NORMAL | 扫描 planner 上下文，登记自身消息 ID（只读，不改写） |
| `maisaka.planner.after_response` | `planner_reply_stripper` | BLOCKING/NORMAL | 生成前剔除命中自回复/重复回复的 reply 工具调用（主拦截；同批去重靠局部 `accepted_targets`） |
| `maisaka.reply.before_post_process` | `reply_round_marker` | BLOCKING/NORMAL | 写轮标记 `_blocked_rounds` / 合法轮写 `_pending_targets`（不在此时登记"已回复"） |
| `send_service.before_send` | `reply_send_abort` | BLOCKING/**LATE** | 发送前兜底 abort（只认轮标记；借出站载荷学习会话类型） |
| `send_service.after_send` | `outbound_id_recorder` | **OBSERVE** | `sent=True` 才把 `_pending_targets` 升级为已回复登记（去重窗口自送达起算）+ 出站台账 |

- 配置四节：`plugin`(enabled) / `self_reply_guard`(enabled, strip_at_planner, abort_at_send, scan_planner_context, track_outbound_ids, exempt_private_chat, id_ttl_seconds=3600, max_tracked_ids=1000) / `duplicate_reply_guard`(enabled, strip_at_planner, abort_at_send, dedupe_window_seconds=180, allow_late_repeat, late_repeat_after_seconds=30) / `intercept_log`(enabled, file_name="intercept.jsonl", max_file_size_kb=1024, backup_count=3, echo_to_main_log, echo_level)。
- 唯一持久化：`self.ctx.paths.data_dir`（即 `data/plugins/github.cateye.duplicate-reply-guard/`）下的 `intercept.jsonl` 及轮转备份。无 SQLite。运行时状态全内存。
- 代码质量高，无 bug 级问题；与主插件无功能重叠（主插件确认无自回复/重复回复拦截、无私聊记忆召回逻辑）。共存关键点：主插件 `outbound_message_enhancer` 在 `before_send` 的 **EARLY**，本插件 abort 在 **LATE**——合并后必须保持这个先后（改写先、拦截后）。

## 5. 阶段 2：主动召回工具（cateye_mai_cross-chat_recall，独立插件阶段先实现）

### 5.1 组件与命名

- 在 `CrossChatRecallPlugin` 上新增 `@Tool` 组件，工具名 `recall_private_chat`。
- 导入：`from maibot_sdk import Tool`；`from maibot_sdk.types import ToolParameterInfo, ToolParamType`（写法范本：`cateye_maimai_recall/plugin.py:306-350`）。
- `brief_description`："召回你与某位群友的私聊记忆"。
- `detailed_description`：写清触发条件（当用户让你回忆与某人的私聊内容、或你需要主动想起与某人私下聊过什么时调用）、限制（只能查当前会话上下文里出现过的用户；传入的名称应取自上下文中的用户昵称）、参数说明、返回说明（失败时 content 会给出原因，可直接转述）。遵循文档实践清单 §13-22：插件内 LLM 工具仅在用户明确要求时调用。
- 参数：`user_name`，`ToolParamType.STRING`，required=True，description="要召回私聊记忆的用户昵称（取当前会话上下文中的名称）"。
- `core_tool`：**默认不设**（走 deferred 池 + tool_search 发现，官方建议默认不设；如用户实测触发不理想，再单独评估改为 core_tool=True）。
- manifest `capabilities` 无需为 Tool 本身新增项；但工具实现用到的 ctx 能力（`message.get_recent`、`chat.get_all_streams`）当前 manifest 已声明，无需变更。

### 5.2 名称解析流程（工具核心逻辑）

入参 `user_name`（strip 后非空，空则按"名称有误"处理）：

1. **候选用户（只查当前上下文）**：取 `kwargs.get("stream_id")`，拉取该聊流最近 `tool.context_window_messages` 条消息，过滤 bot 自身/通知/合成/命令消息（复用 `helpers.extract_message_fields` 的 `is_self/is_synthetic/is_command`），汇总出现过的 `(user_id, nickname)`（nickname = `user_nickname` 优先、`user_cardname` 兜底；**昵称为空的用户不参与名称匹配**）。同一 user_id 保留最新昵称。只匹配昵称，不匹配 QQ 号。
2. **精准匹配**：`nickname == user_name`。命中 1 个 → 进入 5.3；命中 ≥2 个 → 按 5.2.4 返回候选名单。
3. **降级正则匹配**：精准无命中时，对每个候选昵称做 `re.search(user_name, nickname)`；`re.error`（非法模式）时降级为 `re.search(re.escape(user_name), nickname)` 字面匹配。命中 1 个 → 进入 5.3；命中 ≥2 个 → 返回候选名单；命中 0 个 → 返回"名称有误"。
4. **候选名单返回**（模糊命中 ≥2 或精准同名 ≥2）：`{"success": False, "content": "匹配到多个用户，请从以下精准名称中选一个重新查询：A、B、C"}`（名称按最近发言新→旧去重排列；不附带任何私聊内容）。
5. **名称有误返回**：`{"success": False, "content": "名称有误：当前会话中没有找到名称为「<user_name>」的用户。"}`

### 5.3 召回结果与粘性保留

1. 命中唯一用户后查 `store.get(user_id)`；**无记录 / summary 为空 / 已过总结 TTL**（`end_ts < now - store.summary_ttl_hours*3600`）→ 返回 `{"success": True, "content": "你和该用户没有私聊内容。"}`（文案按此原样），**不**注册粘性召回。
2. 有有效总结 →
   - **注册/刷新粘性召回**：`_tool_recall_sticky[stream_id][user_id] = time.time() + tool.recall_retention_minutes*60`（内存 dict，不持久化；每次成功调用刷新该用户的过期时间，即"再次满足召回条件刷新时间"；惰性清理过期条目）。
   - 返回 `{"success": True, "content": <召回内容>}`：内容与注入块同风格——对象昵称、私聊起止时间（`helpers.fmt_ts`，精确到秒）、概括正文。这段文字是给 bot 看的，直接转述可用。
3. **粘性消费**：`on_replyer_before_model_request` 选人时，把当前 stream 的未过期粘性用户**并集**进常规选中用户（去重），统一走 `_apply_injection`。规则：
   - 粘性注入只作用于 **reply**（planner 不做粘性——需求只提到 reply）。
   - 粘性用户在工具调用时已过候选校验，注入阶段**不再过群/用户黑白名单**；但仍受 `plugin.enabled` 与 `inject.inject_reply` 开关控制（`inject_reply=False` 时不注入，工具当轮返回的内容不受影响）。
   - 常规路径因开关/范围/无私聊被跳过时，只要存在未过期粘性用户且 `inject_reply=True`，仍注入粘性块。

### 5.4 新增配置（`tool` 节）

```toml
[tool]                                     # __ui_label__ = "主动召回"
recall_retention_minutes = 5.0             # ge=0.5, le=1440；粘性召回保留分钟数
context_window_messages = 50               # ge=5, le=200；名称候选取最近多少条群消息
```

- `tool` 节加入 `CrossChatRecallConfig`；`SUPPORTED_CONFIG_VERSION` → `0.3.0`，manifest `version` → `0.3.0`。
- 字段遵守 SDK i18n 约定：每字段中文 label + hint + `_ui()` 英文翻译（照抄本插件现有风格）。

## 8. 风险与既定决策
